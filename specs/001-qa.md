## Hallazgos
### QA-011 · BAJA · CA-A4e, A11Y-007
- **Evidencia:** `testAlertLinks` y la aserción de `a.site-logo` en
  `testFocusIndicators` usan `assertMatchesRegularExpression('/color:\s*inherit/', …)`.
  La expresión no está anclada al nombre de la propiedad.
- **Problema:** también daría por buena una declaración `background-color: inherit`
  o `border-color: inherit`. Si alguien cambiara `color: inherit` por una de esas,
  el test seguiría pasando aunque el enlace volviera al color por defecto. Hoy el CSS
  es correcto, así que no hay incumplimiento.
- **Acción propuesta:** anclar la propiedad, por ejemplo
  `'/(^|;|\s)color:\s*inherit\s*(;|$)/'`. Otra opción es separar las declaraciones por
  `;` y comparar la propiedad `color` con `assertSame`. Lo mismo vale para
  `box-shadow:\s*none`, aunque ahí no hay otra propiedad con ese sufijo.

### QA-006 · BAJA · CA6 (abierto desde la 1.ª pasada)
- **Evidencia:** no hay `phpstan.neon` ni `phpstan.neon.dist` en la raíz. La salida
  de PHPStan dice: «PHPStan is performing only the most basic checks … the default
  and current level is 0». Además, `phpcs.xml.dist` no incluye la extensión `css`,
  así que `style.css` no pasa por ningún linter.
- **Problema:** CA6 se cumple (0 errores), pero a nivel 0 la comprobación es
  superficial. Según el agente principal, es configuración del proyecto y queda
  fuera de esta spec.
- **Acción propuesta:** versionar un `phpstan.neon.dist` con un nivel explícito
  (por ejemplo, 5 o 6), en un commit o una spec de infraestructura.

  Search o se añade un bloque. Es el comportamiento buscado: el comentario lo explica.
